# Credits for the Setup page: sources, models, libraries and services

Research for the credits on the Setup page, done on 10 October 2026. The data, service and model entries were checked against the maker's own page (linked in the tables), except for what "Not verified here" at the end lists; the libraries' "Checked" column says which licences were read on the maker's page and which come from the installed package metadata only. Versions come from the running container (`lexflow-app-1`) and from `tools/*/package.json`. The licence column says what the maker's page says. It is not legal advice, and the open questions at the end are for counsel or for the maker.

Inventory sources: `lexflow/pipeline/steps.py` (`STEPS`, one Setup card each, plus the `COMPOSITE` jobs), `requirements.txt`, `tools/web/package.json`, `tools/node/package.json`, `tools/node-alpha/package.json`, the script and link tags in `dashboard/index.html`, `Dockerfile`, `docker-compose.yml`, the "Data sources and licences" table in `README.md`, `docs/core.md`, and every `http(s)://` URL in `lexflow/`, `scripts/`, `dashboard/` and `docker/`.

## Where the credits go

The credits go on the Setup page, attached to the step that uses each source, not on a separate page. Each step card gets one short "Sources" line: the name, the maker, the licence, a link, and a citation when the maker asks for one. Things every page uses (the API server, the store, the diagram viewer, the maps) go in one "Built with" line under the step list. The bpmn.io watermark in the diagram viewer is itself a required credit (see finding 3).

This was proposed here and has since been built: `lexflow/pipeline/credits.py` holds the credits (`name, by, licence, url, use` and optionally `licence_url`, `cite`, `cite_by` and `note`), each `Step` in `steps.py` lists its own, `/api/setup` returns them, and `creditList()` in `dashboard/app.js` renders one line per credit. The suggested wording at the end of this note was the starting point; the credits in `credits.py` are what the page shows.

### How Wikidata and Govdirectory relate

Govdirectory is a view over Wikidata. It is a static site generated from SPARQL queries, maintained by WikiProject Govdirectory, and both its data and its code are CC0. lexflow does not call govdirectory.org. The `contacts` step asks the Wikidata Query Service directly, two queries per state, and matches items to Census governments by FIPS code: P882 for counties and P774 ("51-14968") for places. It reads the same properties Govdirectory shows: P856 website, P968 email and P1329 phone. So the honest credit is "Wikidata (the data behind Govdirectory)", which is what `steps.py` already says. A wrong contact should be fixed on Wikidata, and the fix then shows up in both places. Only office channels are read (organisation websites, office mailboxes and phone numbers), so no person-level records are involved.

## Findings that need a decision

1. **CourtListener's documented limits (since fixed in code).** When this note was written, the card said "one request a second; about a minute per state", and `caselaw.py` waited a second between requests, while new authenticated accounts get 5 requests a minute, 50 an hour and 125 a day (the May 2026 change), and anonymous use is not documented at all. `caselaw.py` now paces every request, retries included, to those three limits, with a 2-second margin on each of CourtListener's windows, through a request log shared by every lexflow process on one data folder (`DATA_DIR/courtlistener-requests.json`). The card's cost line says about four states an hour and ten a day. A run stops at the day's limit and the next one goes on from the states not done yet; a failed search records the state as failed, with the reason, not as "0 opinions". The FLP questions remain open. First, whether a pipeline that stores and republishes case metadata (Turso, the wiki, the Wikibase) fits the "Allowed API usage" policy, which says membership access "may not be used to build tools for for-profit or non-profit organizations". Second, whether the API data has a licence: no FLP page I read states one (the `caselaw.py` docstring used to say "CourtListener's metadata is free to use"; it no longer does). The site's own content is CC BY-ND 4.0 "except where indicated". FLP's free EDU tier is worth a look if lexflow is academic.
2. **Mixed licences on the Lexipedia sites.** Open US Law and LOCUS are CC BY-NC 4.0, and Wikidata is CC0. Wikibase Cloud lets each instance set its content licence on `Project:Copyrights`, and Wikibase's default UI usually tells contributors their edits are CC0. Data derived from a CC BY-NC compilation should not be presented as CC0. Both Lexipedia sites should state which licence applies to the pages and items lexflow loads. The words of a statute are public law, but the compilation is Vaquill AI's. This is for counsel, as the README already says.
3. **The bpmn.io watermark (since fixed).** The dashboard does not touch `.bjs-powered-by`, which is correct. `scripts/viewer_template.html` used to set `.canvas .bjs-powered-by { opacity: .55; }`, but the licence says the watermark must stay "fully visible". The rule has been removed from the template and from the built `out/viewer/lexipedia-viewer.html`. The DokuWiki bpmnio plugin's licence has the same condition.
4. **Privacy.** The dashboard serves every front-end library from `tools/web/node_modules` and makes no CDN calls, so a viewer's browser contacts nobody else. That matches "collect nothing by default". `scripts/viewer_template.html` is different: it loads Google Fonts and bpmn-js from `cdn.jsdelivr.net`, which sends each viewer's IP address to those hosts. It should bundle or self-host them if it is published.
5. **Gemma's notice.** Show "Gemma is provided under and subject to the Gemma Terms of Use found at ai.google.dev/gemma/terms" on the `models` card. Strictly it is required only when redistributing the model, but it costs nothing, and lexflow publishes Gemma outputs in its benchmarks. Google claims no rights in outputs.
6. **Copyleft dependencies.** pm4py and powl are AGPL-3.0-or-later. SpiffWorkflow is LGPL-3.0-or-later, and lexflow patches it. CairoSVG is LGPL-3.0-or-later. SearXNG is AGPL-3.0-or-later, but it runs as a separate, unmodified service. lexflow has no licence yet. When one is chosen, a hosted dashboard that imports pm4py and powl falls under the AGPL network clause, unless PIS's commercial licence is bought. The README already flags pm4py, powl and SpiffWorkflow. CairoSVG is missing from that note.
7. **Gaps in the README's "Data sources and licences" table.** It is missing CourtListener, Hugging Face, Ollama and the three models (especially the Gemma terms), SQLite, bpmn-js and its watermark, d3, topojson-client, DokuWiki, Wikibase Cloud, Turso and libSQL, SearXNG, FastAPI, CairoSVG and Graphviz. It also lacks the LOCUS citation (arXiv:2606.19334) and the Open US Law BibTeX. The README is out of scope for this task. The table above can replace it.
8. **The Census source is frozen.** census.gov says the Government Units Survey was discontinued on 14 April 2025, so this survey will not refresh the 2022 listing. Pinning the `governments` step to the 2022 file is right. The dataset page lists the ZIP as "1.0 MB", but the file actually downloaded is 11,459,763 bytes, which matches the card's "11.5 MB".
9. **Not a dependency.** `docs/core.md` mentions "Legal Data Hunter for citations only", but no code uses it, so it is not credited.

## Suggested wording for each Setup card

- **governments**: Source: U.S. Census Bureau, 2022 Census of Governments, Government Units Listing (public domain). [census.gov](https://www.census.gov/data/datasets/2022/econ/gus/public-use-files.html)
